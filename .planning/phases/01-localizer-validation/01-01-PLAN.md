<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Driver Station/operator -> calibration OpMode | Operator starts/stops motion and relies on displayed calibration state. |
| OpMode -> motors, encoders, and IMU | Software commands physical motion and consumes untrusted/stale hardware readings. |
| Calibration constants -> Localizer math | Invalid or wrong values can create unsafe pose estimates and drive commands. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-01-01 | Denial of service | OdometryCalibrationOpMode motion loop | high | mitigate | Deadline, stop-request check, frozen-sensor detection, and finally-based MecanumDrive.stop(). |
| T-01-02 | Tampering | Localizer calibration values | high | mitigate | Finite/nonzero validation, explicit telemetry contract, and offline guard tests before hardware use. |
| T-01-03 | Information disclosure | Calibration telemetry | low | accept | Telemetry contains robot measurements only; no network, credentials, or stored user data. |
| T-01-SC | Tampering | Build dependencies | high | mitigate | No package installation; use existing FTC SDK and Gradle build only. |
</threat_model>
